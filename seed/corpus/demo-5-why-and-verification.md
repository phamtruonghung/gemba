# 5 Why — how to ask until you reach something you can fix

## Don't count the number of questions

Five is an example number, not a rule. Stop when the answer points to something *fixable*: a missing standard, a check nobody performs, a material nobody owns. If the last answer is "the operator was careless", you have not arrived — keep asking why the system allowed that to happen.

## The rule for going deeper

Each question must rest on an observed fact, not on speculation or a guess about someone's attitude. Go as far as something you can verify by eye or by measurement, then stop.

## Three ways it usually drifts

- Drifting into personal blame instead of working conditions.
- Going outside what you control (say, an overseas supplier shipping late) and stopping there, instead of asking why you had no early-detection buffer.
- Stopping at the nearest cause that was once fixed, without checking whether the old fix is still in force.

## After 5 Why, a countermeasure and a verification date are mandatory

A conclusion without an action, an owner and a verification date is just a conversation. Set checkpoints at about thirty, sixty and ninety days, and write down the result — if it recurs, the root cause was wrong.

## For a problem that keeps coming back

If the same symptom already has an earlier 5 Why, do not start over: read the old conclusion first and check whether the fix still runs. Most recurrences happen because the old fix decayed, not because the analysis was wrong.
